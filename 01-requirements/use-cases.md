
# Use Case: Отправка напоминания о предстоящем автоматическом продлении подписки Travel-сервиса

## 1. Описание Use Case

| Поле | Значение |
| --- | --- |
| **ID / название** | UC-1 / Отправка напоминания о предстоящем автоматическом продлении подписки Travel-сервиса |
| **Актор** | Система-источник события (Travel-сервис), сервис уведомлений |
| **Цель** | Уведомить пользователя о предстоящем автоматическом продлении подписки за 3 календарных дня до даты следующего списания. |
| **Предусловия** | 1. У пользователя активная подписка Travel с включенным автопродлением. 2. Известна дата следующего списания. 3. У пользователя есть действующее согласие на обработку персональных данных. 4. Доступен хотя бы один канал доставки: Push или SMS. 5. Шаблон уведомления доступен системе. |
| **Триггер** | В Kafka поступило событие от Travel-сервиса о предстоящем автоматическом продлении подписки, сформированное за 3 календарных дня до даты следующего списания. |
| **Основной сценарий** | 1. Система получает событие из Kafka. 2. Проверяет идентификатор события на наличие дубля. 3. Определяет категорию уведомления — сервисное. 4. Проверяет действующее согласие пользователя на обработку персональных данных. 5. Проверяет ночные ограничения по таймзоне пользователя. 6. Формирует текст уведомления по шаблону с датой предстоящего списания. 7. Определяет доступность Push как основного канала доставки. 8. Отправляет Push через FCM/APNs. 9. Получает подтверждение доставки и сохраняет статус «доставлено». |
| **Альтернативы** | **A1.** Время отправки попадает в ночное ограничение — отправка откладывается до разрешенного времени. **A2.** У пользователя отсутствует валидный push-токен, но есть подтвержденный номер телефона — уведомление отправляется через SMS без попытки Push. **A3.** Push не доставлен в течение 50 секунд — система выполняет фолбэк на SMS через SMSC.ru и фиксирует результат доставки. |
| **Исключения** | **E1.** SMSC.ru недоступен — уведомление остается в очереди для последующей отправки. **E2.** Отсутствует действующее согласие на обработку персональных данных — уведомление не отправляется. **E3.** Получено повторное событие с тем же идентификатором — повторное уведомление не создается. **E4.** Недоступны оба канала доставки — уведомление не может быть отправлено. |
| **Постусловия** | Пользователь получил напоминание по одному из доступных каналов либо отправка не выполнена с фиксацией причины. Результат отправки и статус доставки сохраняются в системе. |
| **Связанные Story / правила** | US-3; BR-1, BR-2, BR-3, BR-4, BR-5; FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8, FR-10. |

## 2. События для логов

По каждому уведомлению фиксируются идентификатор события, категория уведомления, канал доставки, статус отправки и время события (`timestamp`).

Для повторных событий фиксируется результат проверки на дублирование.

Для отмененных отправок фиксируется причина, в том числе отсутствие действующего согласия на обработку персональных данных.
