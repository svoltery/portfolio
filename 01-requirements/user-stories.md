
# User Story: Напоминание о предстоящем автоматическом продлении подписки Travel-сервиса

## 1. User Story

**ID:** US-3

**Название:** Напоминание о предстоящем автоматическом продлении подписки Travel-сервиса

**Формулировка:**

Как пользователь Travel-сервиса,  
я хочу заранее получать уведомление о предстоящем автоматическом продлении подписки,  
чтобы знать дату следующего списания и при необходимости успеть отменить продление.

**Приоритет:** Must

**Связь:** Бизнес-цель G-2 (снизить количество обращений по поводу неожиданного автопродления подписки на 20%); бизнес-правила BR-1–BR-5; функциональные требования FR-2–FR-8, FR-10; Use Case UC-1.

**Категория уведомления:** Сервисное — не требует отдельного согласия на рекламную рассылку (BR-1), но требует действующего согласия на обработку персональных данных (BR-5) и соблюдения ночных ограничений (BR-3).

## 2. Критерии приемки (Given–When–Then)

### AC-1. Успешный путь: Push доставлен

**Дано:** у пользователя активная подписка Travel с включенным автопродлением, до даты следующего списания осталось 3 календарных дня; есть действующее согласие на обработку персональных данных и валидный push-токен устройства.

**Когда:** система обрабатывает событие о предстоящем автопродлении подписки, время отправки не попадает в период ночного ограничения.

**Тогда:** система формирует уведомление по шаблону с датой предстоящего списания, отправляет Push через FCM/APNs и сохраняет статус «доставлено». SMS не отправляется.

### AC-2. Альтернативный путь: Push не доставлен, фолбэк на SMS

**Дано:** Push-уведомление отправлено, но подтверждение доставки не получено.

**Когда:** истекло 50 секунд ожидания.

**Тогда:** система отправляет уведомление через SMSC.ru и сохраняет результат отправки по резервному каналу (FR-5, BR-4).

### AC-3. Альтернативный путь: отсутствует валидный Push-токен

**Дано:** у пользователя включено автопродление подписки, отсутствует валидный push-токен, но есть подтвержденный номер телефона.

**Когда:** система определяет доступный канал доставки уведомления.

**Тогда:** уведомление отправляется через SMSC.ru без попытки отправки Push.

### AC-4. Отказ: SMS-шлюз недоступен

**Дано:** необходимо отправить уведомление через SMS, но SMSC.ru недоступен.

**Когда:** система пытается отправить SMS.

**Тогда:** уведомление остается в очереди для последующей отправки.

### AC-5. Краевой случай: повторное событие

**Дано:** система ранее обработала событие о предстоящем автопродлении подписки с определенным идентификатором.

**Когда:** из Kafka поступает повторное событие с тем же идентификатором.

**Тогда:** система распознает дубль и не создает повторное уведомление (BR-2, FR-8).

### AC-6. Правило: отправка в ночное время

**Дано:** время отправки уведомления попадает в установленный период ночного ограничения по таймзоне пользователя.

**Когда:** система обрабатывает событие о предстоящем автопродлении подписки.

**Тогда:** уведомление не отправляется в период ночного ограничения; отправка откладывается до разрешенного времени (BR-3, FR-2).

### AC-7. Отказ: отсутствует согласие на обработку персональных данных

**Дано:** у пользователя отсутствует действующее согласие на обработку персональных данных.

**Когда:** система выполняет проверку согласия перед отправкой уведомления.

**Тогда:** уведомление не отправляется (BR-5, FR-7).
