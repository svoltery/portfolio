## 1. Назначение и область действия

Документ фиксирует нефункциональные требования (НФТ) к системе уведомлений розничного блока. Область: прием событий-триггеров из внутренних систем через Kafka, маршрутизация по категориям, отправка через push (FCM/APNs) и СМС (SMSC.ru), учет согласий, тихих часов и приоритетов. Функциональные требования и бизнес-требования вынесены в отдельные документы.

Ключевой принцип домена: уведомления делятся на критичные (безопасность, подтверждение операции, напоминание о платеже) и маркетинговые. У них разные требования к доступности, скорости и правилам отправки. Это различие проходит через все НФТ.

## 2. Термины и сокращения

| Термин | Значение |
| --- | --- |
| p95 / p99 | Процентили времени отклика: 95% и 99% операций быстрее указанного порога. |
| SLA | Целевая доля времени, когда сервис доступен (в процентах). |
| RTO / RPO | Целевое время восстановления после сбоя / допустимый объем потерянных данных во времени. |
| MTBF / MTTR | Среднее время между отказами / среднее время восстановления. |
| at-least-once | Гарантия доставки события хотя бы один раз (возможны дубли, нужна идемпотентность). |
| Идемпотентность | Повторная обработка того же события не приводит к повторному уведомлению. |
| Критичное<br>уведомление | Сервисное, безопасности, подтверждение операции, напоминание о платеже. |
| Маркетинговое<br>уведомление | Промо. Требует согласия, соблюдает тихие часы и частотный лимит. |

## 3. Общие положения

- Каждое НФТ измеримо: содержит метрику, целевое значение и условие (нагрузку, время, окружение).

- У каждого НФТ есть способ верификации и владелец.

- Для критичных и маркетинговых уведомлений применяются разные целевые значения там, где это указано.

- При конфликте требований действует таблица приоритетов (раздел 5).

- Числа-гипотезы не являются обязательствами до согласования с владельцем.

## 5. Приоритеты конфликтующих требований

| Конфликт | Приоритет | Правило разрешения |
| --- | --- | --- |
| Скорость доставки (PERF) vs Безопасность (SEC) | Безопасность | Маскирование ПДн обязательно всегда; для критичных доставку не задерживаем сверх порога, но текст проходит маскирование. |

## 6. Чек-лист готовности НФТ

| # | Проверка | Ок? |
| --- | --- | --- |
| 1 | Есть метрика - что именно измеряем | [ ] |
| 2 | Есть целевое значение - число или диапазон (или TBD с указанием, у кого уточнить) | [ ] |
| 3 | Есть условие или нагрузка - при каком потоке, в какое время, в каком окружении | [ ] |
| 4 | Есть способ верификации - как проверим на приемке | [ ] |
| 5 | Есть владелец | [ ] |
| 6 | Измеримо и однозначно - нет слов-ласок (быстро, надежно, удобно) | [ ] |
| 7 | Разведены критичные и маркетинговые там, где это влияет на значение | [ ] |
