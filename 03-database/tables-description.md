# Описание схемы БД сервиса уведомлений банка

Табличное описание девяти таблиц схемы уведомлений Заначки по итоговой ER-диаграмме: по каждой таблице указаны параметры, тип данных, признак обязательности, ограничения и описание. Там, где тип данных — enum, в этой же колонке перечислены допустимые значения.

## user

Точка входа и место хранения пользователей, необходимых для физической доставки. Без этой таблицы система не может сопоставить `user_id`, пришедший с событием, с клиентом.

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `user_id` | varchar | Да | PK, естественный ключ | Сквозной идентификатор клиента, единый в рамках компании, приходит из мастер-системы банка. |
| `phone` | varchar | Да | NOT NULL | Телефон клиента, нужен для доставки по каналу sms и как контактные данные. |
| `email` | varchar | Нет | — | Email клиента. Пока в схеме не используется как канал доставки, хранится на перспективу. |
| `timezone` | varchar | Да | NOT NULL | Часовой пояс клиента, нужен для проверки тихих часов перед отправкой уведомления. |
| `is_active` | bool | Да | NOT NULL, DEFAULT true | Флаг активности клиента в системе уведомлений. |
| `created_dt` | timestamp | Да | NOT NULL, DEFAULT now() | Дата и время создания записи о клиенте. |
| `updated_dt` | timestamp | Нет | — | Дата и время последнего обновления записи, проставляется при первом изменении. |

## user_device

Хранит техническую информацию, необходимую конкретно для push-канала. У одного клиента может быть несколько устройств.

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | int | Да | PK, суррогатный | Технический идентификатор устройства. |
| `user_id` | varchar | Да | FK → user.user_id, NOT NULL | Ссылка на клиента, которому принадлежит устройство. |
| `push_token` | varchar | Да | NOT NULL | Токен устройства для отправки push-уведомления через коннектор. |
| `platform` | enum (ios / android / huawei) | Да | NOT NULL | Платформа устройства. Определяет, через какой коннектор публиковать сообщение — FCM, APNs или HMS. |
| `is_active` | bool | Да | NOT NULL, DEFAULT true | Флаг актуальности токена. Токен может протухнуть или устройство может быть заменено. |
| `updated_dt` | timestamp | Да | NOT NULL | Дата и время последнего обновления записи об устройстве. |

## user_service

Таблица-связка (многие-ко-многим) между user и service с атрибутом `is_allowed`. Реализует требование «клиент в личном кабинете разрешает/запрещает получать уведомления от конкретного сервиса».

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | int | Да | PK, суррогатный | Технический идентификатор записи о согласии. |
| `user_id` | varchar | Да | FK → user.user_id, NOT NULL | Ссылка на клиента, который дает или не дает согласие. |
| `service_id` | int | Да | FK → service.id, NOT NULL | Ссылка на сервис-источник, на который дается согласие. |
| `is_allowed` | bool | Да | NOT NULL | Согласие клиента на получение уведомлений от этого сервиса. |
| `updated_dt` | timestamp | Да | NOT NULL | Дата и время последнего изменения согласия. |
| — | — | — | UNIQUE (user_id, service_id) | Гарантирует, что пара клиент+сервис не повторяется — у клиента одно согласие на сервис. |

## service

Справочник внутренних систем банка, которые инициируют отправку уведомлений: биллинг, антифрод, маркетинг и другие. Опорная таблица для user_service и notification_template.service_id.

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | int | Да | PK, суррогатный | Технический идентификатор сервиса-источника. |
| `name` | varchar | Да | NOT NULL | Название сервиса, показывается клиенту в личном кабинете при настройке согласий. |
| `description` | varchar | Нет | — | Описание сервиса для клиента, поясняющий текст в личном кабинете. |

## notification_template

Описывает тип уведомления как бизнес-концепцию (например, напоминание о платеже) независимо от текста и канала доставки. Точка, в которой сходятся проверочные условия перед отправкой.

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | int | Да | PK, суррогатный | Технический идентификатор логического шаблона. |
| `template_id` | varchar | Да | UNIQUE, NOT NULL | Код шаблона от системы-источника, по которому входящее событие маппится на нужный шаблон. |
| `category_id` | int | Да | FK → category.id, NOT NULL | Ссылка на категорию, которая задает бизнес-правила обработки (согласие, тихие часы, приоритет). |
| `service_id` | int | Да | FK → service.id, NOT NULL | Ссылка на сервис-владелец шаблона. Критично для определения, чье согласие проверять. |
| `name` | varchar | Да | NOT NULL | Человекочитаемое название шаблона. |
| `created_by` | varchar | Да | NOT NULL | Логин сотрудника, создавшего шаблон — для разбора инцидентов. |
| `updated_by` | varchar | Нет | — | Логин сотрудника, внесшего последнее изменение. Пусто, пока шаблон не редактировали. |
| `created_at` | timestamp | Да | NOT NULL, DEFAULT now() | Дата и время создания шаблона. |
| `updated_at` | timestamp | Нет | — | Дата и время последнего изменения шаблона. |

## notification_template_text

Один логический шаблон доставляется в несколько каналов, и текст под каждый разный. Хранит конкретные варианты текста с приоритетом отправки под каждый канал.

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | int | Да | PK, суррогатный | Технический идентификатор текстового варианта шаблона. |
| `notification_template_id` | int | Да | FK → notification_template.id, NOT NULL | Ссылка на логический шаблон, к которому относится текст. |
| `channel` | enum (push / sms) | Да | NOT NULL | Канал доставки, под который написан этот текст. |
| `channel_priority` | int | Да | NOT NULL | Порядок, в котором пробовать каналы при отправке. Push всегда идет первым. |
| `title` | varchar | Нет | — | Заголовок уведомления, применимо в основном для push-канала. |
| `notification_text` | text | Да | NOT NULL | Текст сообщения под конкретный канал, с плейсхолдерами для подстановки данных. |

## category

Не просто справочник имен, а таблица бизнес-правил: нужно ли проверять согласие клиента, нужно ли учитывать тихие часы, какой приоритет у категории при конкуренции за доставку.

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | int | Да | PK, суррогатный | Технический идентификатор категории. |
| `category` | enum (сервисное / платежное / маркетинговое) | Да | UNIQUE, NOT NULL | Код категории уведомления. |
| `requires_consent` | bool | Да | NOT NULL | Правило: нужно ли перед отправкой проверять согласие клиента на рассылку. |
| `quiet_hours` | bool | Да | NOT NULL | Правило: нужно ли учитывать тихие часы клиента перед отправкой. |
| `priority` | int | Да | NOT NULL | Приоритет категории при конкуренции нескольких уведомлений за доставку одновременно. |

## outbox

Реализует паттерн Transactional Outbox: запись создается в той же транзакции, где принято решение отправить, и переживает возможный сбой публикации в топик. Гарантирует, что сообщение записано, но не говорит о факте доставки.

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | int | Да | PK, суррогатный | Технический идентификатор записи об отправке. |
| `user_id` | varchar | Да | FK → user.user_id, NOT NULL | Ссылка на клиента-получателя уведомления. |
| `template_text_id` | int | Да | FK → notification_template_text.id, NOT NULL | Ссылка на использованный текстовый вариант шаблона. |
| `kafka_message_id` | varchar | Нет | — | Идентификатор сообщения в топике Kafka. Проставляется только после успешной публикации. |
| `status` | enum (new / published) | Да | NOT NULL, DEFAULT 'new' | Статус записи: создана или уже опубликована в топик. |
| `message` | varchar | Да | NOT NULL | Итоговый отрендеренный текст уведомления с уже подставленными данными клиента. |
| `created_dt` | timestamp | Да | NOT NULL, DEFAULT now() | Дата и время создания записи (принятия решения отправить). |
| `published_dt` | timestamp | Нет | — | Дата и время публикации сообщения в топик. Пусто, пока запись не опубликована. |

## delivery_attempt

Фиксирует факт: дошло уведомление до клиента или нет, подтвержденный коннектором. Одно решение отправить может породить несколько попыток доставки во времени (например, фолбэк на sms при неудаче push).

| Параметр | Тип данных | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | int | Да | PK, суррогатный | Технический идентификатор попытки доставки. |
| `outbox_id` | int | Да | FK → outbox.id, NOT NULL | Ссылка на решение об отправке, к которому относится попытка. |
| `is_fallback` | bool | Да | NOT NULL, DEFAULT false | Флаг: является ли эта попытка резервной (например, sms после неудачного push). |
| `status` | enum (delivered / failed) | Да | NOT NULL | Терминальный статус попытки доставки, пишется коннектором один раз, без промежуточных состояний. |
| `attempt_number` | int | Да | NOT NULL | Порядковый номер попытки доставки в рамках одной записи outbox. |
| `created_dt` | timestamp | Да | NOT NULL, DEFAULT now() | Дата и время фиксации попытки доставки. |
